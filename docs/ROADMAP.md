## Useful follow-up work

These are engineering recommendations, not extra organizer requirements for the simulated-experience route:

- Independently test MCP SDK/Inspector interoperability.
- Conduct new-user and operator research; record actual task success and misunderstandings.
- Connect one supported real provider, with clear reservation and cancellation semantics.
- Configure and demonstrate Bedrock only if entering AWS Builder or extending live AI. Adapter code alone is not evidence of usage.
- Add account-based ownership, normalized shared inventory, provider-specific recovery, retention, monitoring and a stronger separate approval authority before real customer use.

Keep the submission focused on a verifiable recovery story. Avoid promising arbitrary payment reversal, sent-message retraction, unrestricted language understanding or a universal marketplace.
